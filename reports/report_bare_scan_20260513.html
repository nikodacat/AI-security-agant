Executive Summary

STONEAI is a gaming PC with solid antivirus and current patches but critically weakened by disabled kernel security features, a zero-length password policy, PostgreSQL exposed on all interfaces, and an unencrypted SSH private key on an unencrypted disk.

This is a high-performance gaming and development workstation running Windows 11 (build 26100) with a solid security baseline in some areas: Windows Defender is fully operational with current signatures, patches were applied as recently as May 12 2026, UAC is properly configured with secure desktop prompting, RDP is disabled, and SMB1 is off. These are genuinely good signs.

However, the machine carries several critical weaknesses that collectively make it vulnerable to any attacker who gains a foothold. The hardware security layer is nearly absent: Memory Integrity (HVCI) is off, ASLR and CFG are not enforced system-wide, and disk encryption is unconfirmed but likely absent. This is compounded by AMD uProf and ASUS Aura SDK — both installed and running — which have documented kernel-level CVEs. The password policy allowing zero-length passwords, PostgreSQL exposed on all network interfaces, and an unencrypted SSH private key on an unencrypted disk create a scenario where a single point of compromise cascades into full data loss.

Top Risks

  • HVCI (Memory Integrity) disabled + AMD uProf kernel CVEs = any local process can achieve kernel-level persistence via a malicious driver without triggering Defender
  • PostgreSQL 18 bound to 0.0.0.0:5432 with a password policy that allows blank passwords = potential unauthenticated database access from LAN or VPN peers
  • Unencrypted SSH private key + no BitLocker = physical access or OS-level compromise gives full SSH identity theft with no passphrase barrier

Quick Wins

  • net accounts /minpwlen:12 — eliminates blank password risk, takes 5 seconds
  • Uninstall WinPcap 4.1.3 — removes EOL kernel driver, Npcap already covers the same functionality
  • Set-NetFirewallProfile -Profile Public -DefaultInboundAction Block — explicit firewall hardening
